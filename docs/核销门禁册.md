# 核销门禁册

> 本册为迟到桶「核销 → 补入」唯一正确性口径。**定稿日：2026-11-20，当天禁止改口。**
> 任何实现偏离本册，写路径必须拒绝并登记 `gate_deviation`（详情固定含「门禁偏了」）。

## 一、选定路径（只此一种）

- **路径：甲 —— 状态机冻结核销。**
- 核销动作在**同一事务**内完成两件事：
  1. `late_bucket.status` 从 `可补入` 切到 `已核销`（写入 `written_off_at` / `written_off_by`）；
  2. 删除 `late_promotable` 中对应 `late_id` 的可补入索引。
- 任一步失败：**状态与索引一并回滚**，不允许出现「状态已核销、索引还在」或反之。
- **禁止路径乙**：不签发 `void_ticket` 票根，不以票根验证作为补入门禁。甲、乙两路**不得混用**；不得新增票根写路径。

## 二、补入前置不变量（硬门禁）

补入（promote）在写正式事件之前，必须在同一桶锁内同时满足：

1. `late_bucket.status = '可补入'`；
2. `late_promotable` 中存在该 `late_id`；
3. 索引行的 `biz_key` / `event_ts` / `amount` 与桶行一致。

任一不满足：**整笔拒补，正式窗零增**，登记 `late_promote_refused`。
禁止仅从队列查询结果里隐藏核销笔；队列、状态、正式事件、审计、争用必须同态。

## 三、并发与锁

- 核销与补入对同一 `late_id` 共用桶锁键：`late-bucket:{late_id}`。
- 先到者持锁；后到者只登记 `contention_log`（`action=争用`），返回 409，**不写任何业务**。
- 两处不得各自造锁键；不得只锁队列或只锁状态。

## 四、五处同态定义

| 落点 | 同态要求 |
|------|----------|
| 可补入队列 `late_promotable` | `status='可补入'` 必有索引；`已核销/已补入` 必无索引 |
| 核销态 `late_bucket.status` | 仅 `可补入 / 已核销 / 已补入` 三态 |
| 正式事件 `events` | `已核销` 无对应正式事件；`已补入` 恰有一条 `promoted_event_id` |
| 审计 `audit_trail` | 核销有 `late_writeoff`；拒补有 `late_promote_refused`；补入有 `late_promote` |
| 争用 `contention_log` | 后到争用有记录且业务零写；无争用时该桶锁无记录 |

## 五、实现落点

- `backend/gate_book.py`：本册的机器可读冻结项 + 拒写守卫。
- `backend/db.py`：`writeoff_gate_book` 冻结表、`late_promotable` 索引表、旧库迁移与索引回填。
- `backend/late_svc.py`：核销 / 补入写路径，统一桶锁。
- `backend/ingest_svc.py`：迟到入桶时同事务写入索引，失败整笔回滚。
- `backend/audit_svc.py`：核销、补入、拒补、门禁偏离五类审计写入口与门禁册查询。
- 网页沿用现有登录与视图，不另起站点；SQLite `data/app.db` 继续由 compose 挂载。
